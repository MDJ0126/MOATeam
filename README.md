## 팀의 업무 흐름

**요청 → 리더의 업무 정리 → 담당자 실행 → 결과 검증 → Git 보관**

- 리더가 업무와 담당자를 정하고 Git 보관 필요성도 판단합니다.
- 검증을 통과한 결과는 담당자 이름으로 프로젝트 브랜치에 기록합니다.
- 산출물은 업무에 맞는 폴더에 두고, 각 폴더의 README에서 목적과 결과를 설명합니다.

## 함께 일하는 팀

| 팀원 | 담당 |
| :-- | :-- |
| 김하준 팀장 | 총괄 · 업무 정리와 배정 |
| 이지우 과장 | 개발 |
| 최서연 대리 | 검증 |
| 박도윤 사원 | 보고 |

## 저장소 구성

```text
examples/
└── git-upload/         실제 VM · Git 연동 검증 예제
    ├── README.md       예제 설명과 검증 방법
    └── result.txt      검증된 결과 파일
```

새 업무는 `work/프로젝트명` 브랜치에서 확인할 수 있습니다. 코드·조사·디자인 등 업무에 맞춰 `projects/`, `research/`, `design/`, `assets/`, `documents/` 폴더를 사용합니다.
